# Unified World Operator-Self-Learning Goal

Last updated: 2026-03-28

## North Star

The system should become a general intelligence stack that solves many tasks through one shared world model, secures its logic with operator algebra, and improves itself through verified memory updates rather than disconnected domain silos.

## Build Doctrine

1. Every domain result must project into the same shared world model.
2. Reasoning must recover hidden goals, blockers, prerequisites, alternatives, and evidence before answering.
3. Operator algebra must explain why a plan or answer holds by exposing decompositions and functor mappings.
4. Self-learning must prefer verifier-backed corrections, retained operators, and reusable world-model memories.
5. RTX 4060 8GB constraints stay active: symbolic-first, local, auditable, and incremental.

## Concrete Implementation Plan

1. Keep extending the unified responder so final answers are generated from common world tasks instead of route-specific heuristics.
2. Keep extending adaptive self-improvement so each run writes:
   - integrated world snapshot
   - integrated reasoning summary
   - operator-algebra learning targets
   - retained evolved operators
   - next learning queries
3. Promote retained operator candidates into reusable memory only after utility scoring and review discipline.
4. Export integrated traces so later small models learn the same world-model structure used at runtime.
5. Use recursive self-evolution to search over improvement programs, but score them partly by shared-world integration quality.

## Immediate Success Criteria

- One run can explain what the current world state is, what blocks progress, what must be verified, and what should be learned next.
- The self-learning loop emits concrete operator-algebra targets instead of vague "improve more" messages.
- Multimodal, ops, math, and CP paths converge on one answer doctrine rather than separate reply styles.

## Closed-Loop Solver Integration

1. Self-learning plans must not remain report-only artifacts; they must drive the next environment probes, grounding repairs, and operator-retention decisions.
2. Environment exploration should be seeded by shared-world guidance queries derived from blockers, prerequisites, evidence, and retained operators.
3. Grounding self-evolution should rank cases and synthesize variants using the same shared-world guidance, so correction pressure stays aligned with the global objective.
4. Operator evolution should bias utility toward operators and basis signatures that the current shared-world plan says matter most.
5. Every guided refinement pass must write back into the same environment source and rebuild the integrated world model again.
